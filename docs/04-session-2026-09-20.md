# 2026-09-20 · USB 制作、测速与回家操作交接

## 当前进度

**已做好用于尝试启动的 CoreELEC U 盘；普通 KM2 实机启动和 CEC 联动均未验证。**
这次只在 Windows 电脑和 U 盘上操作，没有连接或修改盒子，没有刷写盒子的 eMMC、
解锁 bootloader、安装 Android 固件或启动桥接服务。

用户确认的目标为普通 **MECOOL KM2（非 Plus），S905X2-B、2GB+8GB**。
Android 版本、完整 Build、盒子 IP、Apple TV IP 和实际 CEC 地址仍待在家采集。

## 已完成的操作与证据

### 启动盘制作

- 原盘符 D:，USB 磁盘 1，设备名 VendorC ProductCode，序列号 `FC223CE14B011`。
- 物理容量 62914560000 字节（约 62.9 GB / 58.6 GiB）。制作前为 exFAT，
  除 System Volume Information 外没有用户文件。
- 下载官方 `CoreELEC-Amlogic-ng.arm-21.3-Omega-Generic.img.gz`，
  压缩包 SHA-256 与 GitHub release asset digest 一致。
- 解压并写入该 USB，逐字节回读 574619648 字节，与镜像完全一致。

  剩余空间待 CoreELEC 首次启动扩容。Windows 提示格式化 Linux 分区时取消。
- `SYSTEM` 和 `kernel.img` 按镜像随附 MD5 校验通过。
- 将 `device_trees/g12a_s905x2_2g.dtb` 复制为根目录 `dtb.img`，二者 SHA-256 一致。
  这是 S905X2 / 2GB / 百兆网口的通用候选，尚未证明适配普通 KM2。

### 不破坏现有文件的顺序测速

在 FAT 启动分区新建独立临时文件，使用 **128 MiB、1 MiB 块、单次顺序写入和读取**。
通过 Windows 无缓冲 I/O 绕过系统文件缓存；写入采用 write-through，并把最终 flush 计入时间。

| 测项 | 结果 | 耗时 |
|---|---:|---:|
| 顺序写入 | 52.64 MiB/s | 2.432 秒 |
| 顺序读取 | 111.17 MiB/s | 1.151 秒 |

测试文件已删除。测试前后比对的 **92 个现有文件 SHA-256 全部一致**；
系统维护目录 System Volume Information 不在文件哈希比对范围内。
可用空间恢复到 272252928 字节；没有修改分区。
这是当前连接下的短时顺序成绩，未测随机 I/O、长时间持续写入、设备缓存耗尽或整盘健康。

## 调研结论与文档修正

- S905X2 通用支持不代表普通 KM2 整机兼容。
- 检索到的[普通 KM2 官方论坛帖子](https://discourse.coreelec.org/t/coreelec-on-mecool-km2-not-plus-possible/58438)
  没有成功启动方案；不能把 Plus / Plus Deluxe 的结果套到普通 KM2。
- 撤回原文“AV 口内有 recovery 按钮”“零变砖风险”的未经验证说法。
- [刷机步骤](01-flash-coreelec.md)已补全 ADB、只读诊断、一次实验性 USB 启动、
  失败分支与回到 Android 的处理。没有实测 bootloader 状态，不下“永久无法刷机”的结论。

## 回家后按这个顺序继续

1. 在家中电脑 clone 本仓库，或在已有且工作区干净的 checkout 中执行 `git pull --ff-only`。
   阅读本记录及 [01 刷机步骤](01-flash-coreelec.md)，不要仅依赖聊天历史。
2. 准备 KM2、原配电源、电视 HDMI、网线和本次 U 盘；Android 正常启动后记录型号、
   Android 版本、完整 Build 和 IP。
3. 下载 Google Platform-Tools，开启设备实际提供的调试选项，完成 ADB 授权。
   先执行文档第 2 节的只读 getprop 命令；不要先升级、降级或解锁。
4. 按文档第 3 节做一次实验性外置启动，记录端口、执行命令和最终画面。
   若失败，按失败分支判断，停止无依据换固件；U 盘不需要先重新烧录。
5. 若成功进入 CoreELEC，确认扩容、网络、SSH、Python 和 cec-client，再继续接线与脚本工作。
   刷机成功不等于联动功能已经可用。

## 回家后实测结果（2026-09-20 晚）

按上文顺序执行到第 4 步（实验性外置启动）。**结论：普通 KM2 无法从 USB 启动
CoreELEC**，本机退出桥接硬件候选。

### 采集到的设备信息（ADB 只读 getprop）

| 属性 | 值 |
|---|---|
| model / device / product | `LEAP-S1` / `LAS` / `HP4035-Mecool` |
| brand / 代工厂 | MECOOL / SkyworthDigital |
| hardware | amlogic（S905X2-B，G12A） |
| Android | 10（SDK 29），Build `QTT5.200819.003.C2.0.6_20210723` |
| fingerprint | `MECOOL/HP4035-Mecool/LAS:10/QTT5.200819.003/C2.0.6_20210723:user/release-keys` |
| bootloader | `vbmeta.device_state=locked`、`verifiedbootstate=green`、`flash.locked` 为空 |

网络 ADB 在菜单无开关的情况下 5555 仍开放，授权后为 `device`，可执行只读 getprop。

### 外置启动尝试

- U 盘（VendorC）被 Android 正确识别：`SYSTEM`(241 MiB)、`kernel.img`、`dtb.img`、
  `aml_autoscript` 等文件齐全，`dtb.img` 70496 字节对应 S905X2-2G 候选树。
- 先后试 **两个 USB 口**，各执行一次 `adb reboot update`：
  - 第一次：约 55 秒后 `<HOST_IP>` 恢复、ADB 回到 `device`，进 Android。
  - 第二次（换口后）：约 59 秒后同样回到 Android。
- 两次均未出现 CoreELEC 标志，`reboot update` 仅表现为普通重启回 Android。

### 结论与后续

与社区结论一致：普通 KM2 的 bootloader 锁定且加密（Netflix/Google 认证要求），
`reboot update` / aml_autoscript 外部启动路径被拒。**非认证的通用 S905X3/X4 盒子
才是可刷 CoreELEC 的目标**。KM2 本次退出 CEC 桥接硬件候选，后续方向待定：
换通用盒子（脚本/接线/文档全复用，首选）或 Pulse-Eight USB-CEC 适配器 + Linux 主机。
